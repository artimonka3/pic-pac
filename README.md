# PicPac — прототип Phase 1

Интерактивный прототип фотокниг и фотопечати. FastAPI проверяет оригиналы и подтверждает тестовые заказы. Макет книги собирается в браузере, правки доступны вручную и через чат с локальными правилами.

## Запуск

```bash
docker compose up -d --wait postgres
uv sync --locked
npm ci
```

В первом терминале запустите API, во втором — Vite.

```bash
uv run --locked uvicorn main:app --host 127.0.0.1 --port 8000
```

```bash
npm run dev
```

Откройте http://127.0.0.1:5173/

Для проверки сборки выполните `npm run build`, затем `npm run preview`. Оба режима Vite проксируют `/api` в FastAPI на порту 8000. [Swagger](http://127.0.0.1:8000/docs)

Если PostgreSQL уже запущена, задайте `DATABASE_URL` вместо запуска контейнера. По умолчанию API использует `postgresql://picpac:picpac@127.0.0.1:5432/picpac` и создаёт таблицы при старте. Оригиналы и превью хранятся в `.picpac/media`. Каталог можно изменить через `PICPAC_MEDIA_DIR` и следует сохранять вместе с базой. Для HTTPS включите `PICPAC_SECURE_COOKIE=1` и направьте запросы `/api` в FastAPI на том же домене, что и фронтенд.

## Сценарий

1. Главная → **Создать фотокнигу** или каталог Lite / Classic / Premium.
2. Загрузка оригиналов и проверка фотографий на сервере, затем тема, стиль и пожелания.
3. Экран генерации с этапами → готовый макет из отдельных HTML-страниц и блоков.
4. Редактор: развороты, лента миниатюр, страница, макет, фото, фон, кадр, текст, чат.
5. **В корзину** → **К оформлению** → подтверждение тестового заказа.
6. Проекты, корзина и настройки профиля хранятся в `localStorage`. История новых заказов загружается с сервера.

Демонстрационные книги уже в списке проектов (минимум 12 страниц, разные компоновки).

## Демонстрационный режим

- Генерация макета — локальная имитация с задержкой, без нейросетей
- Чат редактора меняет макет по ключевым фразам в браузере
- Цены и характеристики — тестовые данные, не оферта
- Оформление заказа — без оплаты и производства
- Уведомления в профиле не отправляют письма
- Демо-фото в `public/photos` взяты из Unsplash

## Проверка оригиналов и заказ

- `POST /api/session` создаёт анонимную сессию с HttpOnly cookie. Черновик, фото и заказ привязаны к владельцу сессии.
- `PUT /api/drafts/{draft_id}/media/{media_id}?service=book|print` принимает байты исходного JPEG или PNG. Сервер проверяет формат, декодирование, ориентацию EXIF и лимиты 12 МБ и 24 Мп. Для интерфейса создаётся отдельное JPEG-превью без EXIF.
- `GET /api/media/{media_id}` возвращает `pending`, `passed`, `needs_replacement` или `failed`. Временный сбой можно повторить через `POST /api/media/{media_id}/retry` до трёх попыток на снимок. Замена получает новый идентификатор. Воркер читает очередь из PostgreSQL и восстанавливает прерванные задачи.
- `POST /api/orders` проверяет владельца, черновик и статус каждого выбранного фото, рассчитывает цену и сохраняет заказ. Повтор с тем же `Idempotency-Key` и телом возвращает тот же заказ. Публичные демо-книги доступны без загрузки. Старые пользовательские загрузки требуется повторить с оригиналов.
- Приватный оригинал доступен владельцу подтверждённого заказа через `GET /api/orders/{order_id}/media/{media_id}/original`. Панель сотрудника, лента и публикация во внешние сервисы пока не подключены.

Стартовые пороги заданы в `backend/media/rules.py`. Для книги требуется от 1200 × 800 px, для фотопечати — от 1800 × 1200 px по длинной и короткой стороне. На уменьшенной копии OpenCV измеряет экспозицию и резкость. До калибровки на реальных снимках проблемы со светом и смазом дают предупреждения.

`backend/media/model.py` задаёт точку подключения классификатора. Только для пограничной резкости правила передают ей RGB-копию 224 × 224 с полями. Заглушка возвращает `None`, поэтому сохраняется предупреждение OpenCV. Ошибка классификатора также оставляет решение правил.

## Проверки

```bash
PICPAC_TEST_DATABASE_URL=postgresql://picpac:picpac@127.0.0.1:5432/picpac uv run --locked python -m pytest -q
npm run build
```

Тесты API создают временные схемы PostgreSQL. Без `PICPAC_TEST_DATABASE_URL` запускаются тесты обработки фото.

## Структура

```
src/
  pages/          # экраны приложения
  components/     # UI, книга, навигация, загрузка
  data/           # продукты, темы, библиотека фото
  lib/            # клиент API, сборка книги, правила чата
  store/          # Zustand + persist
  styles/         # глобальные токены
backend/
  media/          # загрузка оригиналов, очередь, OpenCV, заглушка классификатора
  orders.py       # подтверждение заказов и выдача оригиналов
  schema.sql      # схема PostgreSQL
```
